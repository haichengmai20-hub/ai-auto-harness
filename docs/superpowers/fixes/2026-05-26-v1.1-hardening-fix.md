## 现象

v1.0 实施完成后(5/22 SongGen e2e 试跑 2 次)集中暴露**LLM 自觉度极低**问题:
- R1-R9 规则在 SKILL.md 里被 LLM 忽视(自由发挥)
- cron 启动遗留僵尸进程,新 worker 与旧 worker 抢资源
- launch_worker 没明确强调 R 规则,SubAgent 进入后没人提醒
- 多个 skill 落盘约定不一致(每个 skill 自己写 phase 标记格式)

---

## 触发条件 / 复现步骤

1. v1.0 上线后跑 SongGen run2 → 暴露 sleep loop(R4 来源)+ 主/子越权(R1+R9 来源)
2. 跑 SongGen baseline 对比 → 暴露 cache + pip + GPU preflight(R5+R6+R7 来源)
3. cron 没 trap cleanup,失败后 PID 文件不清,下次启动时旧 PID 还在
4. SubAgent 进入后不知道 R 规则存在 → 自由发挥

---

## 影响

- **影响范围**: 平台运行可靠性 + 跨 run 隔离 + LLM 行为约束
- **影响下游**: 所有 SubAgent / 所有 cron run / 所有 hook
- **严重程度**: P0 — v1.0 到 v1.1 的关键加固,不修则平台无法多项目并存

---

## 根因

- **是否已确认**: ✅
- **简述**:
  > v1.0 实现快、但**约束在 SKILL prompt 里被忽视**:
  > 1. CLAUDE.md 没有顶层硬规则,各 skill 各自约定不一致
  > 2. 没有实时检测机制(LLM 违反规则后没人当下提醒)
  > 3. cron 启动姿势粗糙(无 trap、无 PID 标记、无防僵尸)
  > 4. SubAgent 拿不到 system prompt 强调,容易"忘"

---

## 修复方案

### 设计层修改(R1-R9 整合)

- [x] `.claude/CLAUDE.md` 加 **R1-R9 硬规则**(整合多个前期 fix):
  - R1 workspace 隔离(来自 [agent-isolation-fix](2026-05-21-agent-isolation-fix.md))
  - R2 state.json phase 双写(开始 + 结束)
  - R3 phase wall-clock 上限 + 超时写 pending_human
  - R4 禁 sleep loop(来自 [sleep-loop-discipline-fix](2026-05-21-sleep-loop-discipline-fix.md))
  - R5 串行带宽(来自 [baseline-3-blockers-fix](2026-05-21-baseline-3-blockers-fix.md))
  - R6 pip 反模式(同上)
  - R7 `hf` 不 `huggingface-cli`(同上)
  - R8 PHASE_START/END 标记
  - R9 其他(主 agent 不亲自 bash + verify 独立判定)

### 实现层修改

- [x] `.claude/hooks/post-tool-use.sh` 改成 **python3 实现的 PostToolUse 硬约束 hook**:
  - 实时检测 R1/R4/R6/R9 违规
  - 通过 `hookSpecificOutput.additionalContext` 注入 LLM 下一 turn(LLM 看到当下提醒)
- [x] `cron/launch_worker.sh` 加:
  - `trap cleanup EXIT`
  - 启动前扫僵尸 + `kill $(cat *.pid)` 清前任
  - `worker.pid` 写自己 PID
  - `--append-system-prompt` 反复强调 R 规则给 SubAgent
- [x] `cron/daily.sh` 加同样 trap + PID 管理
- [x] 6 个 SKILL.md 适配 R8 PHASE 标记格式统一(`=== PHASE_START phase=X slug=Y run_id=Z ts=... ===`)
- [x] `memory/lessons/torch-sm12.md` 追加 "requirements.txt pin 冲突剥离" + "numpy 降级" 经验
